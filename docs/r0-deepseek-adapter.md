## Public API and ownership

- `src/host/command-queue.ts`: `new CommandQueue()` and `enqueue(sequence => synchronousValue): Promise<Value>`. The assigned FIFO sequence is the linearization order; callbacks returning thenables are rejected. Every host mutation/confirmation/AI revocation and callback must use **this same instance**. Never make a callback async.
- `src/ai/index.ts`: exports `AiAuthority(queue, initial)`, `AiLedger(queue, sqlitePath, frozenManifest)`, `AiGateway(authority, ledger, access, credentialProvider, deadlineMs=60000)` plus DTOs and protocol helpers. Gateway checks identity of authority and ledger queue. SQLite path is supplied only by the trusted host. Use a durable, private local file in production, never `:memory:` as persistence evidence.
- Authority initial fields: `{authEpoch,adultEnabled,sessionId,writerToken,projectId,scopeEnabled}`. `setAdult(boolean)`, `setScope(boolean)`, `replaceWriter(sessionId,writerToken,projectId)` enqueue mutations; all increment epoch and revoke outstanding eligibility even if the value is unchanged. `snapshot()` is a read-only clone. The host must also invalidate candidates on these changes. This layer has no ProjectStore write/apply method.
- Gateway `submit(input:unknown):Promise<GatewayResult>` validates a strict `SubmitRequest`: `{requestSlotID,requestId,idempotencyKey,snapshot,document,repairOfAttemptId?}`. Snapshot exactly follows D07; input Document is validated/cloned and rehashes its actual content, then must match the snapshot. Supplied document must originate from the authoritative host snapshot; host admission must reject stale live Store revision before calling, and candidate/confirm must recheck current revision again.
- `gateway.cancel(requestId)` enters the same queue, persistently cancels that logical request and aborts current transport wait. `shutdown()` revokes records and aborts but does not refund or reset. On host restart create a fresh session/writer identity; never restore an old live authority binding from the ledger. The persisted ledger still blocks new requests if any reserved/in_flight/unknown attempt remains.
- `credentialProvider():Promise<string|null>` is the only credential input, supplied by root's host module. It runs outside the queue; immediately afterward the gateway **re-enters** the queue and rechecks all authority/config/cancellation/budget gates before a synchronous dispatch call. No key/env path is sent, logged, serialized or placed in the browser. A preparation failure consumes no provider attempt; a stable request with zero attempts can be resubmitted.

## Payload and response default

The sole outbound builder explicitly constructs projectId/requestId/baseRevision/baseSemanticHash and trusted versions, ≤300 UTF-16 intent, bounded scene/rules/presentation, the two frozen theme mappings, six trusted rule IDs and an explicit no-events marker. It never serializes the request snapshot wholesale: authEpoch/session/writer, titles/notes, local paths and arbitrary extra fields are not sent. The input bound counts all serialized request UTF-8 bytes plus a 1024 framing allowance as a conservative token reservation; exceeding 12000 rejects without truncation. Full reservation uses 12000 input and 4096 output tokens every attempt.

This initial T06 interface deliberately supports `selectedEvidenceRefs:[]` only. T08 must add the selected actual @3 projection, original run rules and provenance binding before any AI11 request; passing nonempty references is rejected. This prevents a generic JSON context from becoming a vault/trajectory exfiltration path. Parent choices/child-slot provenance are not implemented here; T07 host must gate them using actual parent output and recorded human choice before submit. This module is adapter foundation, not completion of T07/T08.

The response DTO single engineering default is exported as `responseSchema` and TypeScript `ModelResponse`; strict Ajv rejects unknown keys, illegal kinds, unknown operations and operations on any read-only kind:

- directions: `{kind,summary,options:[{id,label,rationale}]}`, 2–3 unique options.
- locate: `{kind,summary,reasonCode:"manual_quantity"|"rule"|"entity",entityIds,ruleIds}`. Entity/rule references are checked. Quantity has no operations/apply endpoint.
- explain: `{kind,summary,facts:[{text,eventIds}],rules:[{text,ruleIds}],hypotheses:[{text,test}],options}`. Event refs must currently be empty because no actual events are supplied. This is not evidence fidelity/semantic approval.
- propose: `{kind,summary,operations}` using the existing seven-operation Schema, 1–3 operations. This yields **untrusted suggestion data**; T05 must build/validate/hash/trial the full candidate.
- clarify: `{kind,question}` (≤300 units), no new automatic request slot.
- unsupported: `{kind,reason}`.

Strings are bounded and code fences/script/URL payloads are rejected for product parsing. Original returned content stays in `AttemptRecord.rawOutput` as controlled untrusted evidence; the UI must render only the validated DTO using text-safe templates. Invalid/free-text/empty/truncated outputs never partly apply. User intent and model semantic correctness still need the frozen human review; strict Schema is neither permission nor truth.

## Persistent accounting and stop rules

`node:sqlite.DatabaseSync`, WAL, synchronous=FULL, BEGIN IMMEDIATE. One SQLite ledger is bound to the exact canonical frozen manifest digest, 38 unique logical slots and exact A1/A2 attempt IDs. A slot/request/idempotency key conflict rejects. Only SHA256 payload/key digests are stored for idempotency; session/writer strings are not stored. Original per-attempt result rows remain available; repeat identical submits return the stored last result or an in-progress duplicate receipt. Duplicates do not send again. Every explicit repair retains requestId/slot, uses the next frozen attempt ID, and requires first attempt actually `invalid_response` with valid usage known; canceled/stale/unknown requests cannot repair. No automatic repair loop.

Money uses safe integer nanoCNY (1 CNY = 1,000,000,000). Peak input CNY2/M (2000 nano/token), cache hit CNY0.04/M (40 nano/token), output CNY8/M (8000 nano/token). Each attempt reserves `12000*2000+4096*8000=56,768,000 nanoCNY` = CNY0.056768, below CNY0.06. At most 76 attempts reserve CNY4.314368 and 1,223,296 total tokens; the CNY20 ceiling remains separately enforced. No off-peak discount is relied upon. Any count/token/money/concurrency/permission limit stops before a new dispatch.

Reservation and dispatch marker are separate durable records in the synchronous queue boundary. If the process dies after either, the slot/reservation survives; it is never reset to zero on reopen. Synchronous transport invocation failure is conservatively unknown. Missing/malformed usage, failed HTTP, abort, timeout or unknown transport retains reservation **and** single-flight occupancy, blocking subsequent attempts. No speculative refund/reconciliation API is exposed. An actual complete late response with valid bounded usage may account transport occupancy, but revoked/canceled eligibility never returns; a missing/over-cap usage remains unknown.

Known usage is `usage_calculated_pending_bill`, never settled/actual billed; cost calculation uses peak cached/noncached rates. Full peak reservations continue counting against caps even when usage is smaller. Billing reconciliation and official evidence remain future host operations; no current API clears unknowns or makes unsettled billing pass. Gateway deadline engineering default is 60 seconds; the actual timeout probe must record whether timeout was really observed, and may not fake a timeout or add slots.
